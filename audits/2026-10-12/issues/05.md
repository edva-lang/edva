**5. High — Narrow integer division and remainder produce invalid LLVM IR. Reproduced.**

- Signed division (`narrow_div/main.dva`, archived with the report): `a = i8(100); b = i8(3); io::out $ a / b` fails LLVM verification.
- Unsigned remainder (`narrow_mod/main.dva`, archived with the report): `a = u16(100); b = u16(3); io::out $ a % b` also fails verification.

The guard constructs zero, minimum signed value, and minus one as i64 regardless of operand width ([expr.dva:2230](https://github.com/edva-lang/edva/blob/bc20a35ba2dd351bb0c891797a33d1ec8ae74940/src/codegen/expr.dva#L2230)). Example emitted instruction: `icmp eq i8 %var.load1, i64 0`. Generate constants and overflow checks at the actual operand width, covering all signed/unsigned widths and both `/` and `%`.

Audit: 2026-10-12, finding 5, Edva checkout `bc20a35ba2dd351bb0c891797a33d1ec8ae74940`. Local project report: `audits/2026-10-12/report.md`. Source permalinks above identify the audited GitHub revision; this Gitea repository is the existing Edva issue tracker.

**Reproduction: narrow_div**

```dva
#use io
a = i8(100)
b = i8(3)
io::out $ a / b
```

Observed exit status: `1`.

```text
E5011: LLVM module verification failed: Both operands to ICmp instruction are not of the same type!
  %div.is.zero = icmp eq i8 %var.load1, i64 0
Both operands to ICmp instruction are not of the same type!
  %div.is.min = icmp eq i8 %var.load, i64 -9223372036854775808
Both operands to ICmp instruction are not of the same type!
  %div.is.negone = icmp eq i8 %var.load1, i64 -1

E5011: Compilation aborted due to code generation errors.
```

**Acceptance criteria**

- [ ] Zero and signed-overflow checks use the actual operand width and correct minimum value.
- [ ] Cover normal results, division by zero, and signed minimum divided by -1.
