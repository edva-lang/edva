**4. High — Arena generation encoding fails during ordinary long-running loops. Reproduced.**

The generation reproduction (`arena_generation_wrap/main.dva`, archived with the report) performs 65,538 iterations, creates `"a" + "b"`, and immediately reads its length. It aborts with E4010 despite using each string before that iteration's restore.

Only 16 generation bits fit into a string length, because the generation is shifted left by 48 ([expr.dva:326](https://github.com/edva-lang/edva/blob/bc20a35ba2dd351bb0c891797a33d1ec8ae74940/src/codegen/expr.dva#L326)). Validation compares the extracted 16-bit tag against an unrestricted 64-bit generation ([expr.dva:172](https://github.com/edva-lang/edva/blob/bc20a35ba2dd351bb0c891797a33d1ec8ae74940/src/codegen/expr.dva#L172)). At generation 65,536 the stored tag becomes zero, which also means immortal; later tags disagree with the full counter. Simply masking the counter would introduce stale-generation reuse and retain the zero/immortal collision. This needs a defined epoch/region lifetime strategy with an exhaustion policy.

Audit: 2026-10-12, finding 4, Edva checkout `bc20a35ba2dd351bb0c891797a33d1ec8ae74940`. Local project report: `audits/2026-10-12/report.md`. Source permalinks above identify the audited GitHub revision; this Gitea repository is the existing Edva issue tracker.

**Reproduction: arena_generation_wrap**

```dva
#use io
0..65538 @ i =>
   s = "a" + "b"
   ?s != 2 | io::out("bad")
io::out("done")
```

Observed exit status: `1`.

```text
E4010: stale String read after arena restore
E5014: Compiled program exited with code 1
```

**Acceptance criteria**

- [ ] Freshly allocated strings remain readable across more than 65,536 restores.
- [ ] Document and implement generation exhaustion without conflating live tags with immortal tag zero or reviving stale allocations.
- [ ] Add boundary tests around 65,535/65,536 and a stale-allocation regression.

Run each reproduction separately with the audited compiler using `timeout 15s ./edva main.dva -r` and a 4 GiB virtual-memory limit. A timeout is expected for the current tombstone-hang reproduction.
