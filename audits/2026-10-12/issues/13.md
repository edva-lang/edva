**13. Design/implementation contract — Layout metadata disagrees with lowering. Static plus a size probe.**

The semantic layout describes Rune as 4 bytes ([layout.dva:33](https://github.com/edva-lang/edva/blob/bc20a35ba2dd351bb0c891797a33d1ec8ae74940/src/layout.dva#L33)); LLVM lowering gives it the i64 fallback ([types.dva:1127](https://github.com/edva-lang/edva/blob/bc20a35ba2dd351bb0c891797a33d1ec8ae74940/src/codegen/types.dva#L1127)), and the local size probe (`rune_size/main.dva`, archived with the report) prints 8 for `#size(Rune)`. It also reports Error as 48 bytes, while `codegen_build_error` allocates its 56-byte record ([main.dva:1729](https://github.com/edva-lang/edva/blob/bc20a35ba2dd351bb0c891797a33d1ec8ae74940/src/codegen/main.dva#L1729)). The same module hard-codes eight-byte raw pointers even though the compiler supports 32-bit targets. This is demonstrably inconsistent metadata; this audit has not established a resulting memory overwrite. Separate logical layouts, value representations, allocation sizes, and foreign ABI layouts, and compute target-dependent quantities centrally.
