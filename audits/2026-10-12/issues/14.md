Gitea issue: [#137](https://gitea.gde.to/ike/dva/issues/137)

**14. Quarto references contain executable contradictions. Reproduced where indicated.**

| Reference claim | Actual behavior / conflicting evidence |
|---|---|
| [The first Quickstart program uses `print` without an import](https://github.com/edva-lang/edva/blob/bc20a35ba2dd351bb0c891797a33d1ec8ae74940/doc/start/quickstart.qmd#L19) | The exact two-line example (`quickstart_hello/main.dva`, archived with the report) fails E3004 (`Undefined function: print`). Use an explicit `#use io` and `io::out`. |
| [Integer examples use `x: i8 = 127`](https://github.com/edva-lang/edva/blob/bc20a35ba2dd351bb0c891797a33d1ec8ae74940/doc/reference/types/int.qmd#L22) | Probe (`doc_inline_annotation/main.dva`, archived with the report) fails E2003. The Addr page correctly requires a separate annotation line. |
| [Integer comparisons use `<=` and `>=`](https://github.com/edva-lang/edva/blob/bc20a35ba2dd351bb0c891797a33d1ec8ae74940/doc/reference/types/int.qmd#L109) | Probe (`bad_comparison/main.dva`, archived with the report) fails E2027; valid spellings are `!>` and `!<`. Rune examples repeat the invalid forms. |
| [Signed right shift is arithmetic](https://github.com/edva-lang/edva/blob/bc20a35ba2dd351bb0c891797a33d1ec8ae74940/doc/reference/types/int.qmd#L95) | Code uses logical right shift; the grammar also says logical. This is separate from the narrow-width bug. |
| [String + Int formats decimal text](https://github.com/edva-lang/edva/blob/bc20a35ba2dd351bb0c891797a33d1ec8ae74940/doc/reference/types/string.qmd#L141) | Probe (`string_int_append/main.dva`, archived with the report): `"item_" + 42` produces `item_*`. Integer append writes a byte. Use `str::from_int` or formatting. |
| [String indexing returns `<String|Error>`](https://github.com/edva-lang/edva/blob/bc20a35ba2dd351bb0c891797a33d1ec8ae74940/doc/reference/types/string.qmd#L154) | `"A"(0)` returns byte value 65, and applying `!!` is rejected (probe (`string_index_unwrap/main.dva`, archived with the report)). Out-of-bounds String indexing aborts rather than returning an error ram. |
| [Typed raw-memory store `@[addr T] = val`](https://github.com/edva-lang/edva/blob/bc20a35ba2dd351bb0c891797a33d1ec8ae74940/doc/guide/data-and-memory.qmd#L134) | The [Addr reference](https://github.com/edva-lang/edva/blob/bc20a35ba2dd351bb0c891797a33d1ec8ae74940/doc/reference/types/addr.qmd#L94) correctly says this is E2093; writes use `@[addr] = typed_value`. |
| [Quickstart calls all bindings strictly immutable and forbids uninitialized declarations](https://github.com/edva-lang/edva/blob/bc20a35ba2dd351bb0c891797a33d1ec8ae74940/doc/start/quickstart.qmd#L61) | Primed bindings are reassignable; declaration plus definite field initialization is supported and documented elsewhere. |
| [Quickstart formatting call passes format first](https://github.com/edva-lang/edva/blob/bc20a35ba2dd351bb0c891797a33d1ec8ae74940/doc/start/quickstart.qmd#L180) | The probe (`quickstart_printf/main.dva`, archived with the report) prints `128`, losing the message. `io::outf` expects value first, format second. |

The array page also combines inline annotation syntax with a slice example and presents a named-loop form `@loop:` that is not the documented cycle grammar. Its complete slice declaration snippet fails parsing (probe (`slice_doc/main.dva`, archived with the report)). These snippets should become executable documentation fixtures, with intentionally incomplete syntax illustrations explicitly marked.

**Reproduction: quickstart_hello**

```dva
message = 10 > 5 | "greater" | "smaller"
print $ message
```

Observed exit status: `1`.

```text
main.dva:2:1: E3004: Undefined function: print
main.dva:2:1: E3103: Cannot infer concrete type for expression without RTTI
E5011: Compilation aborted due to code generation errors.
```

```text

```

**Reproduction: bad_comparison**

**Reproduction: string_int_append**
